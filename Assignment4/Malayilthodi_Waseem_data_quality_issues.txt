Dataset reviewed: sales_data_dirty.csv

1. Missing Product values
Some records do not contain a Product value. A sales record without a product name cannot be grouped or reported reliably by product, so these records need to be identified and handled before analysis.

2. Missing Quantity values
Some records have a missing Quantity. Because quantity is required for basic sales analysis and for interpreting an order, these incomplete records need to be handled rather than silently used in calculations.

3. Duplicate records and repeated OrderID values
The dataset contains duplicate records, and OrderID should be checked for repeated values because it functions as an order identifier. Exact duplicates can double-count sales if they remain in the dataset.

4. Invalid or unreasonable Quantity values
The Quantity field contains values that are not logical for a normal completed sales order, including negative or zero quantities and an extremely large value of 1000. I used a documented business rule that keeps positive quantities from 1 through 100 and removes values outside that range.

5. Text consistency check
The Product and Customer fields are checked with table() and whitespace/casing cleanup. The supplied data does not contain a Region or CustomerID column, even though those fields appear in the generic sample prompt in the assignment instructions. I therefore cleaned the actual fields supplied in the CSV rather than inventing columns that are not present.
