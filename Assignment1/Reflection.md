## Reflection 1 - AI-Assisted Documentation

Using AI helped me organize the documentation faster by suggesting a
logical README structure and consistent Markdown formatting. It was
especially useful for identifying sections such as Overview,
Installation, Example Code, Inputs, Outputs, and AI Assistance
Disclosure.

The main weakness is that an AI-generated draft can look complete even
when details still need to be checked. For that reason, I treated the
generated content as a draft rather than assuming it was automatically
correct.

## Reflection 2 - Verification and Refinement

The most important part of the workflow was reviewing the output after
generation. I checked the heading hierarchy, fenced code blocks, lists,
project structure, and consistency between the README and R Markdown
document.

I also refined the draft by shortening repetitive wording, making the
project purpose clearer, adding explicit inputs and outputs, and keeping
the R example simple enough to reproduce. The final verification step is
to preview the README on GitHub and knit or preview the `.Rmd` file in
RStudio.

## Reflection 3 - Ethical Use of AI

AI was used as a documentation and formatting assistant. I disclosed the
tool, date, prompts, and changes made after reviewing the output. I did
not provide personal data or a real dataset to the AI. The example uses
synthetic data only.

This process showed me that AI can improve speed and presentation, but
responsibility for verification remains with the person submitting the
work. Clear attribution and manual review are important because they
make the workflow transparent and reduce the risk of submitting
unverified content.
